# 04 · 列表设计

只有「表单+列表」类型才有这一步。

## 列配置

点「添加列」→ 勾选字段 → 确定。列标题与格式化会按控件类型**自动推断**，再逐列微调。

- **列顺序就是这张表的行序**，拖左侧把手调整
- **宽度类型**：最小宽度（内容撑开）/ 固定宽度
- **固定列**：左固定 / 右固定。⚠️ 固定列**不能参与复杂表头分组**

### 格式化

| 类型 | 说明 |
|---|---|
| 字典翻译 | 显示中文而不是编码 |
| 标签 | 同上，但渲染成带颜色的标签。颜色按值自动分配，同一个值每次颜色一致 |
| 日期 / 日期时间 | 按格式显示 |
| 数字 | 小数位 + 千分位 |
| 百分比 | ⚠️ 要声明**库里存的是小数（0.15）还是百分数（15）**，选错差 100 倍 |
| 布尔值 | 显示「是 / 否」 |
| 图片 / 附件 | 渲染成缩略图 / 带原文件名的链接。**点附件是下载**，不是在新窗口里打开它 |
| 超链接 | 渲染成可点的链接。只放行 http/https/mailto/tel 与相对地址，其余降级成纯文本 |

> 配字典类型的地方（字典翻译、标签、查询下拉、左侧树）都是**树形选择**，
> 下拉里印的是字典名称、编码作为浅色附注 —— 字典类型本身有层级，
> 分组节点只用来归拢、挂不了字典数据，所以它在树上是不可选的。

### 合计行

勾「显示合计行」，再选要合计的列。选了非数值列时会有提示 —— 合计行对它显示成「-」。

## 查询条件

每个查询项配三样：**字段、查询控件、操作符**。

**查询控件按字段类型自动推断**，也可以手工改：

| 控件 | 渲染成 | 可用操作符 |
|---|---|---|
| 文本框 | 输入框 | 包含 / 等于 / 不等于 / 左包含 / 右包含 / 区间 / 为空 / 不为空 |
| 下拉选择 | 字典下拉（**用户选中文，发出去的是编码**） | 等于 / 不等于 / 在范围内 / 为空 / 不为空 |
| 日期 | 日期选择器 | 等于 / 大于等于 / 小于等于 / 大于 / 小于 / 为空 / 不为空 |
| 日期区间 | 日期区间选择器 | 区间（固定） |
| 数字 / 数字区间 | 数字输入框 | 比较类 / 区间 |
| 是 / 否 | 是否下拉 | 等于 / 不等于 |

超过三个查询项时查询区默认折叠。**被折叠起来的查询项仍然参与查询** ——
收起不等于清空。

## 按钮

按钮是一份**有序清单**，每一项可以改文案、换图标、调顺序、显隐。

- **工具栏**：新增、导出、批量删除、批量打印
- **行内**：编辑、详情、变更记录、打印、删除

**把「删除」放在「编辑」右边能明显降低误点率。**

批量删除 / 批量打印会自动在表格上加多选列；没配这两个按钮就不加 ——
放一列勾选框却没有任何批量操作可用，用户会一直找那个「然后呢」。

> 「变更记录」要数据绑定里开了变更日志才会出现，「打印」要配了打印模板才会出现。
> 勾了但对应配置没到位时，运行时不会渲染它 —— 设计器里会给出提示。

### 操作列与按钮折叠阈值

操作列本身可以配标题、宽度，以及**按钮折叠阈值**（默认 3）。

行内按钮超过这个数量时，多出来的收进行尾的「更多」下拉。原因是操作列
固定在表格右侧，它撑多宽，数据列就少看多宽 —— 配齐五个内置按钮再加两个
自定义按钮，一行七个按钮，表格能看的部分只剩一半。

- 折叠只是**换个位置**，按钮一个都不会少，顺序也不变
- 内置按钮与自定义按钮合在一张清单里算折叠，不会折出「三个 + 更多 + 两个 + 更多」
- 只多出一个时不折 ——「三个按钮 + 一个下拉」比四个按钮还宽，还多一次点击
- 设计器里改这个数字会当场告诉你哪几个直接显示、哪几个进下拉，不用存一次再去列表页看

## 高级

### 行内编辑

开启后，点「编辑」不再弹窗，就地把这一行变成可编辑控件，**每行单独保存**。

- 要到「列配置」里逐列勾「可编辑」。只开开关不勾列，没有任何效果
- 图片、附件、超链接列不支持（要专门的编辑器，单元格也放不下）
- 与明细列互斥
- 走的是与弹窗编辑**同一条**提交流水线：必填、格式校验、跨字段校验、乐观并发锁全都照常生效

### 标签页筛选

按某字段的值把列表切成几个页签。切页签等价于追加一个等值条件，
与查询区的条件是**叠加**关系。「全部」页签由运行时自动补在最前面，不用配。

### 树形列表

自关联建树：配「父级字段」与「主键字段」。

**⚠️ 与分页互斥**，开树形会自动关掉分页 —— 分页按行数截断，会把父行留在上一页、
子行推到下一页，子行找不到父节点就从树里整个消失。

### 左侧树查询区

列表左边挂一棵树，点节点按某字段筛选。

- **字典源**：节点取自字典项。字典本身是树形的话，左侧树也是多层的；
  点父节点会**连同它的全部后代一起匹配**
- **表单字段源**：节点取自该列的实际去重值，最多 500 个

### 复杂表头

把相邻几列归到一个父表头下。**固定列不能参与** ——
Element Plus 算固定列偏移量时不考虑多级表头，两者并用会错位。

### 明细列

把子表的字段放进列表：一条主记录会被**摊平成多行**，主表列纵向合并。

⚠️ 明细列与树形列表、行内编辑三者互斥 —— 三种重排合不到一起。

## 这些配法会静默失效

| 配法 | 表现 |
|---|---|
| 开了行内编辑但一列都没勾「可编辑」 | 点编辑进了编辑态，但没有任何东西能改 |
| 百分比列的「库里已是百分数」选反 | 数值差 100 倍，而且看起来很像正常数据 |
| 标签 / 字典列没配字典类型 | 显示原始编码 |
| 合计列选了文本列 | 合计行显示「-」 |
| 固定列放进了复杂表头分组 | 表头与内容错位（设计器已把固定列排除在可选项外） |
| 查询项选了明细字段 | 明细字段在主表查询里不存在，条件被服务端忽略 |
| 排序列选了明细列 | 排序作用在主表查询上，按明细值排主记录没有确定语义 |
