# 02 · 表单设计

## 控件分三类

按「值怎么落库」分，这决定了它该绑什么类型的列：

| 落库形态 | 含义 | 列该开成 | 属于这一类的控件 |
|---|---|---|---|
| `scalar` | 单值，直接进列 | 按值的类型开（varchar / decimal / date…） | 单行文本、多行文本、密码、数字、开关、单选、下拉、树选择、日期、时间、滑块、评分、颜色、单图上传、签名、富文本、关联表单、远程选择、公式、字典选择、单据编号 |
| `delimited` | 多值，落库是**分隔串** | `varchar`，**要留够长度** | 多选、级联、树形控件、穿梭框、日期区间、时间区间、省市区 |
| `json` | 落库是一段 JSON 文本 | `text` / `longtext` | 附件上传、多图上传、组织架构选择 |
| `none` | 纯展示，**不占列** | —— | 提示、分割线、按钮、图片、标签、超链接、条码、内嵌页、系统值、分组标题、栅格、卡片、折叠面板 |

**⚠️ 选错列型的后果**：多选控件绑到 `int` 列上，提交时会报一个看不懂的数据库错误；
绑到长度不够的 `varchar` 上，则是**存的时候被截断**，读回来少几项而不报错。

## 字段 ID 必须等于物理列名

这是整个模块最重要的一条约定。设计器里字段 ID 是从物理列下拉里选的，正常配天然满足。

手工改成别的名字之后：提交成功、库里数据正确、**但打开详情那个字段是空的**。
运行时的查询不给列起别名，返回的键就是列名。

## 布局

- **分组标题**（`fcTitle`）：可以设成「可折叠」，用来把长表单切成几段
- **栅格**：一行放几个控件
- **标签页 / 步骤条**：把表单切成几步。两者都支持「当前步必填没填就不许往下走」，
  且只拦往后走、不拦往回退

> 步骤条有两套实现并存（老的挂在标签页上、新的是独立容器），**不要去合并它们** ——
> 已有表单用的是老那套，改掉等于动别人的表单。两边的校验语义是刻意保持一致的。

## 属性面板

选中控件后在右侧配。常用的几项：

- **标题 / 字段 ID / 必填 / 占位提示**
- **默认值**：日期类支持「相对日期」（如「今天」「本月一号」）。
  **存的是 token 不是具体日期** —— 存具体日期的话，它在表单发布的第二天就过期了
- **出现场景**：控制这个字段在「新增/编辑」还是「详情」里出现
- **选项来源**（选项类控件）：静态数据 / 数据字典 / 数据接口，三选一互斥，见 [08](08-数据字典与数据接口.md)
- **格式校验**（文本类控件）：内置正则库，见 [06](06-校验与数据质量.md)

## 子表（一对多明细）

拖「子表」控件，把明细字段拖进它内部。

**⚠️ 子表的内部规则挂在 `props.rule` 下，不是 `children`。** 手写配置时容易搞错，
写进 `children` 的话那些字段会被当成主表字段，提交时往主表塞不存在的列。

子表支持：行数区间限制、行内必填、合计行、行复制、行内公式（按行求值）。

## 这些配法会静默失效

| 配法 | 表现 |
|---|---|
| 字段 ID 与物理列名不一致 | 提交成功、库里对，详情里那个字段是空的 |
| 多选类控件绑到长度不够的 varchar | 存的时候被截断，读回来少几项，不报错 |
| `elTreeSelect` 开多选 | 它的落库形态是 scalar（单值），开多选等于往单值字段塞数组 |
| 上传类控件绑到 varchar(500) 以下 | 多文件时 JSON 超长，发布校验会拦；单图不会拦但可能截断 |
| 纯展示控件配了字段映射 | 它不产生值，那一列永远是空的 |
| 同一列被两个字段映射 | 提交时报 `Column 'xxx' specified twice` |
