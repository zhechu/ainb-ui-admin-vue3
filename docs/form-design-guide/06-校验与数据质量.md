# 06 · 校验与数据质量

## 校验分几层

| 层 | 在哪配 | 谁执行 | 示例 |
|---|---|---|---|
| 必填 | 控件属性 | 前端 + 服务端复校验 | 校验示例 2 |
| 格式（正则） | 控件属性 → 格式校验 | 前端 + 服务端 | 校验示例 1 |
| 跨字段 | 表单级 | 前端 + 服务端 | 校验示例 2 |
| 联动驱动的动态必填 / 只读 | 表单级联动规则 | 前端 + 服务端（仅 SUBMIT 时机） | 校验示例 3 |
| 唯一性 | 控件属性 | 失焦查一次 + 提交时再查一次 | 校验示例 4 |
| 子表行数 / 行内必填 | 子表控件属性 | 服务端 | 校验示例 5 |
| 值长度 | 自动（按列长度） | 服务端 | 校验示例 4 |
| 脚本组合校验 | 表单级脚本 | **仅前端** | 校验示例 6 |
| 查库 / 算法校验 | 服务端扩展点 | 仅服务端 | 校验示例 7 |

**除脚本那一层外，服务端全部都会再判一遍。** 前端校验是为了即时反馈，不是安全边界。

七个校验示例发布在【基础设施 → 开发示例 → 在线开发】下。每个示例的列表里都掺了
**故意违规的脏数据**（直接写库塞进去的 —— 走接口根本提交不进来）：
点「编辑 → 保存」就会被服务端拦下。这比读文档更能说明「为什么服务端必须再判一遍」。

## 格式校验

在控件的属性面板里配，位置在最下面一段：**格式校验** + **内容不能重复**。
只有四个文本输入控件有这一项（单行输入、多行输入、密码、数字输入）——
下拉、单选这类控件的值来自选项，值域已经由选项决定，再配正则只会带来
「选项里有个值不匹配正则，用户选了却提交不了」这种没法自救的死局。

用内置正则库（手机号、邮箱、身份证、URL…），不用自己写正则。

> 内置正则都落在 Java 与 JS 的公共子集内，保证前后端判定结果一致。
> 自己写正则时注意：不要用后顾断言、不要用 `\p{...}`。

## 跨字段校验

「A 必须满足与 B 的某种关系」，例如：

- 结束日期 ≥ 开始日期
- 售价 ≤ 标价

配的是一条断言（`must`）加一句报错文案。断言不成立就拦住提交。

## 唯一性

给字段勾「唯一性校验」：失焦时查一次、提交时服务端再查一次。

**⚠️ 都不能替代数据库唯一索引。** 并发下两次检查可能都通过。
真要保证唯一，加唯一索引；这里的校验是为了给用户一个即时提示。

> 唯一性接口只对配了唯一性的字段生效 —— 否则它就成了一个
> 「任意列 + 任意值 → 存在与否」的探测口。

这件事在校验示例 4 里是**跑出来的**，不是写在文档里的：
`demo14_verify_quality.py` 会起 8 个线程同时提交同一个信用代码，断言**恰好成功 1 条**。
去掉唯一索引，这条断言立刻变红。

### ⚠️ 唯一索引与逻辑删除天然冲突

删掉的行还在表里，仍占着那个值。常见绕法是把 `deleted` 一起纳进唯一键
`(uscc, deleted)` —— 但 `deleted` 只有两个取值，同一个值最多容纳两行，
**第三次删除照样撞键**。真要两者兼得，得引入「删除批次号」这类每次删除都不同的列。

校验示例 4 的取舍是：那张表不开逻辑删除，用物理删除。

## 子表约束

- **行数区间**：最少 / 最多几行
- **行内必填**：明细的某列必填

报错会带**行号**（从 1 开始，与界面一致）。同一列多行缺失会合并成一条
（「第 1、2、3 等 30 行」），而不是刷屏 30 条。

## 值长度

服务端按物理列的长度拦超长值，并且会告诉你是哪个字段、超了多少。
不拦的话数据库会**静默截断**，而截断过的数据几乎不可能事后发现。

## 脱敏

给字段配脱敏规则后，读取路径（列表、详情、导出）返回的都是掩码后的值。
**明文不会下发到前端**。

在属性面板的「数据脱敏」里选：手机号、身份证、银行卡、姓名、邮箱，外加一个「自定义」。
选了策略之后可以改**补位符**（默认 `*`）；选「自定义」时还能指定前后各保留几位。

值比要保留的位数还短时会被**整体遮掉**
—— 一个只有 3 位的「手机号」若按「保留前 3 后 4」处理会原样输出，等于没脱敏；
脏数据不该成为脱敏的绕过口。

哪些控件能配，由控件契约里的 `maskable` 决定（当前是单行输入、多行输入、密码）。
不是随便哪个控件都该有这一项：值来自选项的控件遮掉之后用户没法辨认自己选的是什么。

> 脱敏只影响**读**。库里存的始终是明文，改这项不需要迁移数据，
> 关掉之后历史数据照常显示完整值。

## 报错信息的几条约定

- 用字段**标题**而不是字段 ID —— 用户看不懂 ID
- 子表报错带**行号**
- 同类错误**一次性汇总**，而不是改完一处、再提交又被拦下一处
- 同一条规则若有前后端两条路径，两边的**措辞要一致**。
  唯一性就是这种情况：失焦时前端查一次、提交时服务端再查一次，
  两句话不一样的话，用户会以为自己撞上的是两种不同的限制。
  当前两边共用「在系统里已存在，不能重复」，由
  `form-design-verify-demos.spec.ts` 的「信用代码重复」一条同时钉住两条路径

## 这些配法会静默失效

| 配法 | 表现 |
|---|---|
| 以为唯一性校验能代替唯一索引 | 并发下仍会插入重复数据 |
| 自己写的正则用了 Java/JS 不通用的语法 | 前端放行、服务端拦住（或反过来） |
| 子表明细列配唯一性 | **不支持**：语义不明确（同一单据内不重复？还是整张明细表不重复？） |
| 列长度改小但没重新发布 | 发布时才会重算元数据缓存，改完要重新发布一次 |
| **联动规则只配 LOAD / CHANGE，没配 SUBMIT** | 服务端复校验会把它整条滤掉 —— 界面上必填，接口提交空值却成功 |
| **子表行数写成 `minRows` / `maxRows`** | 内核用的键名是 `min` / `max`，写错则界面限制住了、服务端放行 |
| 指望脚本的 `beforeSubmit` 拦住什么 | 脚本跑在浏览器里，构造一个请求就绕过了。能声明式表达的要另配一份规则 |
| 实现了服务端扩展点但表单没切 `extensionMode = 2` | 钩子一次都不执行、也不报错（启动日志里只有一条 WARN） |
| USCC 里写了 `I O S V Z` | 国标 GB32100 排除了这五个字母，内置正则会判不通过（这条踩过两次） |

## 怎么验收

```bash
cd ruoyi-vue-pro/script/form-demo
python smoke_verify.py token.txt
```

29 条**反例**：每一条都绕过前端直接构造违规请求，断言服务端拦住了、
且报错是**预期的那一条**（只断言「失败了」是没有价值的 —— 表名写错也会失败）。
