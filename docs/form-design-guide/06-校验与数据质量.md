# 06 · 校验与数据质量

## 校验分几层

| 层 | 在哪配 | 谁执行 |
|---|---|---|
| 必填 | 控件属性 | 前端 + 服务端复校验 |
| 格式（正则） | 控件属性 → 格式校验 | 前端 + 服务端 |
| 跨字段 | 表单级 | 前端 + 服务端 |
| 唯一性 | 控件属性 | 失焦查一次 + 提交时再查一次 |
| 子表行数 / 行内必填 | 子表控件属性 | 服务端 |
| 值长度 | 自动（按列长度） | 服务端 |

**服务端全部都会再判一遍。** 前端校验是为了即时反馈，不是安全边界。

## 格式校验

用内置正则库（手机号、邮箱、身份证、URL…），不用自己写正则。

> 内置正则都落在 Java 与 JS 的公共子集内，保证前后端判定结果一致。
> 自己写正则时注意：不要用后顾断言、不要用 `\p{...}`。

## 跨字段校验

「A 必须满足与 B 的某种关系」，例如：

- 结束日期 ≥ 开始日期
- 售价 ≤ 标价

配的是一条断言（`must`）加一句报错文案。断言不成立就拦住提交。

## 唯一性

给字段勾「唯一性校验」：失焦时查一次、提交时服务端再查一次。

**⚠️ 都不能替代数据库唯一索引。** 并发下两次检查可能都通过。
真要保证唯一，加唯一索引；这里的校验是为了给用户一个即时提示。

> 唯一性接口只对配了唯一性的字段生效 —— 否则它就成了一个
> 「任意列 + 任意值 → 存在与否」的探测口。

## 子表约束

- **行数区间**：最少 / 最多几行
- **行内必填**：明细的某列必填

报错会带**行号**（从 1 开始，与界面一致）。同一列多行缺失会合并成一条
（「第 1、2、3 等 30 行」），而不是刷屏 30 条。

## 值长度

服务端按物理列的长度拦超长值，并且会告诉你是哪个字段、超了多少。
不拦的话数据库会**静默截断**，而截断过的数据几乎不可能事后发现。

## 脱敏

给字段配脱敏规则后，读取路径（列表、详情、导出）返回的都是掩码后的值。
**明文不会下发到前端**。

## 报错信息的几条约定

- 用字段**标题**而不是字段 ID —— 用户看不懂 ID
- 子表报错带**行号**
- 同类错误**一次性汇总**，而不是改完一处、再提交又被拦下一处

## 这些配法会静默失效

| 配法 | 表现 |
|---|---|
| 以为唯一性校验能代替唯一索引 | 并发下仍会插入重复数据 |
| 自己写的正则用了 Java/JS 不通用的语法 | 前端放行、服务端拦住（或反过来） |
| 子表明细列配唯一性 | **不支持**：语义不明确（同一单据内不重复？还是整张明细表不重复？） |
| 列长度改小但没重新发布 | 发布时才会重算元数据缓存，改完要重新发布一次 |
