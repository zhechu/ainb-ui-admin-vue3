# 08 · 数据字典与数据接口

选项类控件（下拉、单选、多选、级联、树选择、树形控件）的选项有三种来源，**三选一互斥**。

## 一、静态数据

直接在属性面板里维护选项。适合三五个固定值且不会被别处复用的场景。

## 二、数据字典

选一个字典类型，选项就是它的字典项。

- 字典支持**树形**（父子结构），树选择类控件能直接用
- 字典项的颜色会被列表的「标签」格式化用上

### ⚠️ 字典必须通过界面/接口维护，不能直接写库

前端的字典是**带版本号的本地缓存**：登录时先用本地那份把页面撑起来，
再问后端要一个版本号，一致就不重新拉。而版本号只在走字典的增删改**接口**时才递增。

直接 `INSERT` 进字典表的后果是：库里有、后端接口查得到，**但前端永远拿不到** ——
表现为列表里的字典列渲染成空白单元格、下拉框一个选项都没有，
而且要清浏览器缓存才会好。

## 三、数据接口

选一条已登记的数据接口，选项来自它的返回值。**不用填 URL，也不用写解析函数。**

配置项：

| 项 | 说明 |
|---|---|
| 接口 | 从已登记的接口里选。**按编码引用**，不是自增 ID |
| 显示字段 | 支持 `${a}（${b}）` 这种组合写法 |
| 取值字段 | 选项的值取哪个字段 |
| 入参 | 见下 |
| 缓存 | 无入参的接口可以开；入参会变的**不要开** |

### 入参可以取自表单字段

这是「选了部门、人员下拉跟着变」的做法：

- **入参来源**选「表单字段」，再选绑哪个字段
- 依赖字段一变，选项立刻重取，并且**清掉已选值** ——
  换了部门，原来选的那个人多半不在新部门里

### ⚠️ 接口用编码引用而不是 ID

表单在环境之间迁移时 ID 会变、编码不会。用 ID 的话，导到另一套环境上
那个下拉会**静默变空**：接口存在、表单也在，就是取不到数。

### 发布校验会拦什么

- 引用了不存在的接口
- 入参映射引用了不存在的字段 —— 不拦的话它会静默传空值，
  接口按空值查返回空列表，表现为「下拉一个选项都没有」而配置看起来完全正常

## 这些配法会静默失效

| 配法 | 表现 |
|---|---|
| 直接写库造字典 | 前端永远拿不到，字典列空白、下拉无选项 |
| 有入参的接口开了缓存 | 依赖变了选项不变，停在第一次取到的那批 |
| 接口用 ID 引用 | 换环境后下拉静默变空 |
| 显示字段写了返回值里没有的键 | 选项渲染成空白行 |
