## 校验与扩展能力覆盖

这批能力此前**零示例覆盖**，由七个校验示例补齐。

| 能力 | 示例 | 演示要点 |
|---|---|---|
| 内置正则库（18 个 key） | 校验示例 1 | 全覆盖，含正反样本对照 |
| 自定义正则 | 校验示例 1、5 | 必须落在 Java 与 JS 的公共子集内 |
| 同字段叠加多条规则 | 校验示例 1 | 逐条判，先不过的先报 |
| 空值不校验格式 | 校验示例 1 | 「非必填 + 有格式」清空后能正常提交 |
| 跨字段：恒真断言 / BETWEEN / IN / 字段间比较 / 嵌套 AND-OR | 校验示例 2 | 七条规则覆盖条件模型的全部表达力 |
| **联动规则（10 种动作全覆盖）** | 校验示例 3 | 含「配了 / 没配 otherwise」的 A-B 对照组 |
| **联动的服务端复校验** | 校验示例 3 | 不可写字段丢弃、必填拦截、规则冲突报错 |
| **自定义按钮** | 校验示例 3 | TOOLBAR / ROW，`visibleWhen` 复用同一棵条件树 |
| **字段脱敏（5 种策略 + 自定义）** | 校验示例 4 | 列表 / 详情 / 导出三条读取路径都遮；属性面板「数据脱敏」可配 |
| 值长度守卫 | 校验示例 4 | 报错说明哪个字段、超了多少 |
| 唯一性 + 唯一索引 | 校验示例 4 | 8 线程并发验证，断言恰好成功 1 条 |
| **子表行数区间** | 校验示例 5 | 键名是 `min`/`max`，另有 1000 行硬顶 |
| 子表行内必填 / 行内格式 | 校验示例 5 | 报错带行号，同列多行合并成一条 |
| 公式服务端权威重算 | 校验示例 5 | 篡改合计后提交，入库的是重算值 |
| **前端脚本（4 个钩子）** | 校验示例 6 | 含超时阻断、「内核必填先于 beforeSubmit」 |
| **服务端扩展点** | 校验示例 7 | 全项目第一个实现，兼作参考实现 |

> 校验示例 7 的扩展点做的是**正则做不到**的事：身份证校验码加权和、跨记录查库查重、
> 工号生成、已转正后的状态机约束。代码在
> `yudao-module-infra/.../service/formdesign/extension/demo/VerifyStaffExtension.java`。

## 怎么复核

```bash
# 控件覆盖 + 各示例用到的控件数
python coverage.py token.txt

# 校验能力：29 条反例，绕过前端直接提交，断言服务端拦住且报错是预期的那条
python smoke_verify.py token.txt

# 界面这一层由 e2e 守着
cd yudao-ui-admin-vue3
npx playwright test form-design-demos
```

e2e 会核对每个示例的演示数据齐全（每个配出来的列都有值），
以及那些「配了容易不生效」的能力真的生效了。
