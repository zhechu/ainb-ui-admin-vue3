## 表格示例（G01–G12）

十二个示例共用一个数据域（项目台账 60 条 + 里程碑 174 条 + 费用明细 232 条 + WBS 22 条）。
共用一批数据是有意的：表格能力之间要横向对比，各用各的数据就比不出来了。

| # | 示例 | 演示什么 |
|---|---|---|
| G01 | 基础与列格式化 | 十一种格式化各摆一列，直接对比同一个值配不同格式化的样子 |
| G02 | 冻结列与宽表 | 29 列横向滚动；左固定编号与名称、右固定操作列；两种宽度类型对比 |
| G03 | 多级分组表头 | 五组两级表头。⚠️ 固定列不能参与分组，所以本示例一列都不固定 |
| G04 | 合计行与明细合计 | 主表列与明细列两种合计口径；合计行跟随列自己的格式化 |
| G05 | 主子表展开与跨行合并 | 两张明细表同时展开，行数不等时短的那张留空；无明细的主记录仍占一行 |
| G06 | **同值单元格合并** | 类型→阶段→负责人三列级联；空值不合并；必须配默认排序 |
| G07 | **行分组与分组小计** | 分组行带条数与两列小计、可折叠；分组按值归并，不依赖排序 |
| G08 | 树形台账（WBS） | 四层自关联建树，树形与合计并用 |
| G09 | 左侧树与标签页双维筛选 | 两个筛选维度叠加，是「与」的关系 |
| G10 | 行内编辑与批量操作 | 数字/下拉/日期/开关四种行内编辑器；批量删除、导出、变更记录 |
| G11 | **表格打印** | 列表打印（分组表头 + 合并 + 合计都印得出来）+ 单据打印的明细行 |
| G12 | **富展示单元格与列设置** | 图片/签名/附件/超链接/标签五种非文本列；运行时列设置 |

加粗的四项是这一批新做的能力。构建脚本在
`ruoyi-vue-pro/script/form-demo/demo_grid_*.py`，端到端在
`tests/e2e/form-design-grid-demos.spec.ts`（47 条）。

### 这一批顺带修掉的缺陷

| 缺陷 | 原先的表现 |
|---|---|
| 合计行不跟随列格式化 | 数据行 `1,234`、合计行 `1234.00`，同一列上下像两套数 |
| 合计取的是重排后的表格行 | 行分组下合计变成一排 `-`；树形下合计恒为 0 |
| 「合计列」候选漏判公式列 | 金额合计十有八九合的就是公式列，却被提示「看起来不是数值列」 |
| 打印模板的成对循环段扛不住编辑器 | 在设计器里打开保存一次，明细就印不出来（HTML foster parenting） |
| `coverage.py` 只数 `type` | 「文字」「间距」统计不到，覆盖率一直差两个 |

## 怎么复核

```bash
# 控件覆盖 + 各示例用到的控件数
python coverage.py token.txt

# 校验能力：29 条反例，绕过前端直接提交，断言服务端拦住且报错是预期的那条
python smoke_verify.py token.txt

# 界面这一层由 e2e 守着
cd yudao-ui-admin-vue3
npx playwright test form-design-demos
```

e2e 会核对每个示例的演示数据齐全（每个配出来的列都有值），
以及那些「配了容易不生效」的能力真的生效了。
