# 01 · 快速上手

从零配出一张「能增删改查的表单」。以一张任务清单为例。

## 第 0 步：先有表

表单设计**绑的是已经存在的物理表**，它不会替你建表。先把表建好：

```sql
SET NAMES utf8mb4;   -- ⚠️ 不写这句，Windows 下中文注释会静默变成乱码

CREATE TABLE test_demo_task (
    id          bigint       NOT NULL COMMENT '主键',
    task_name   varchar(128) DEFAULT NULL COMMENT '任务名称',
    task_state  varchar(32)  DEFAULT NULL COMMENT '任务状态',
    plan_date   date         DEFAULT NULL COMMENT '计划完成日期',
    creator     varchar(64)  DEFAULT '' COMMENT '创建者',
    create_time datetime     NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    updater     varchar(64)  DEFAULT '' COMMENT '更新者',
    update_time datetime     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    version     int          NOT NULL DEFAULT 0 COMMENT '乐观锁版本',
    deleted     bit(1)       NOT NULL DEFAULT b'0' COMMENT '是否删除',
    PRIMARY KEY (id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='任务清单';
```

几个列是「约定俗成配套」的，强烈建议都留着：

| 列 | 作用 | 不留会怎样 |
|---|---|---|
| `creator` / `create_time` / `updater` / `update_time` | 审计列，由后端自动填 | 查不出「谁在什么时候建的」 |
| `deleted` | 逻辑删除 | 删了就真没了，误删无法恢复 |
| `version` | 乐观并发锁 | 两个人同时改同一条，后提交的会覆盖先提交的，且双方都以为存成功了 |

## 第 1 步：新建表单

【基础设施 → 表单设计 → 新增】。

- **表单编码**：运行时与菜单引用它，发布后不建议再改
- **表单类型**：
  - *纯表单* —— 一张独立的提交页，没有记录列表
  - *表单+列表* —— 上面是列表、点行弹出表单。**大多数场景选这个**

## 第 2 步：表单设计

从左侧面板拖控件到画布，右侧属性面板配细节。

**⚠️ 这一步最要紧的一条**：控件的「字段 ID」必须与物理列名**完全一致**。

设计器里字段 ID 是从物理列下拉里选的，正常配出来天然一致。但如果手工改成别的名字，
表现是：提交能成功、库里数据也对，**但打开详情时那个字段是空的**。
原因是运行时查询不给列起别名，返回的键就是列名，与字段 ID 对不上。

## 第 3 步：数据绑定

选主表、主键、主键策略，并把每个表单字段映射到物理列。

- **主键策略**：雪花（推荐，导出导入时保号）或自增
- **审计填充**：把四个审计列挂上，模式选「系统自动填充」
- **逻辑删除**：勾上，列选 `deleted`
- **乐观并发锁**：勾上，列选 `version`

详见 [03 · 数据绑定](03-数据绑定.md)。

## 第 4 步：列表设计

选要显示的列、配查询条件、配按钮。详见 [04 · 列表设计](04-列表设计.md)。

最省事的做法：点「添加列」→ 全选 → 确定。列标题与格式化会按控件类型自动推断出来，
再逐列微调。

## 第 5 步：发布

点「发布」，选一个上级菜单。发布做四件事：

1. 校验整套配置（配错的地方会在这里被拦住，报错信息会说清是哪个字段）
2. 存一份版本快照
3. 建菜单与四个按钮权限
4. 把表单状态改成「已发布」

**⚠️ 新建的菜单不会自动分配给角色。** 需要去【系统管理 → 角色】把它勾给对应角色，
再**重新登录**一次 —— 前端的动态路由是登录时按菜单一次性注册的，不重新登录看不到新菜单。

## 第 6 步：在浏览器里走一遍

新增一条、改一条、查一次、删一条。

这一步不能省。这个模块里绝大多数缺陷的表现都是「保存成功了但没生效」，
而保存成功、发布成功都不能说明配置真的在工作。

## 改完之后

草稿改动**不会自动生效**，要再点一次「发布」。运行时读的是已发布版本，
只保存不发布的话，界面上还是旧的 —— 这是设计如此，不是 bug。
