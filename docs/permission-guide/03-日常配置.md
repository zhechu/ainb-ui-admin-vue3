# 03 · 日常配置

按「我要做什么」组织。每节都写清入口在哪、坑在哪。

---

## 给角色配权限

**入口**：【系统管理 → 角色管理】→ 目标角色那行的「资源授权」

弹窗分两块：上面是这个角色已有的授权列表，下面是「新增授权」。

### 授权列表能看到什么

| 列 | 说明 |
|---|---|
| 资源 | 授权对象，鼠标悬停看完整权限串 |
| 动作 | VIEW / CREATE / … / `*` |
| 效果 | 允许 / 拒绝 |
| 行过滤规则 | 挂了哪条规则，空表示不限制行 |
| 字段模式 | 仅对列/字段资源有意义 |
| 到期时间 | 空 = 永不过期；已过期会标红 |

### 新增一条授权

资源用树形选择器挑。**树是按资源的父子关系展开的**，
动作和效果必填，其它可空。

> ⚠️ 新增之后建议立刻用普通账号验一次。授权配错不会报错，
> 只会表现成「菜单没出来」或「按钮点了报无权限」。

---

## 管理行过滤规则

**入口**：【系统管理 → 规则管理】

这里维护的是**可复用的规则定义**，不是「给谁配」。给谁配是在授权行上挂规则。

### 新增规则

选一个内置模板，界面会提示这个模板要不要填参数、依赖哪个槽位。

内置模板清单见 [01 · 快速上手](01-快速上手.md#内置规则速查)。

### 停用 vs 删除

- **停用**：规则还在，但不再出现在授权配置的下拉里。已经挂了它的授权**仍然生效**。
- **删除**：彻底删掉。

**内置种子规则（id ≤ 13）不能删**，只能停用——它们是系统初始化的，
删了会影响别处引用。界面上点删除会报错。

## 资源配置面板

从角色授权弹窗、字段权限页签、或流程权限配置都能打开它。五个页签：

### 授权列表

这个资源上的**全部**授权，不分主体。排查「谁能看这张表」时从这里看最快。

### 槽位映射

告诉行过滤规则「哪一列是归属人/部门/状态/业务主键」。

| 操作 | 说明 |
|---|---|
| 新增 | 填槽位名 + 真实列名。同一资源同一槽位名不能重复 |
| 修改 | 一般只改列名 |
| 删除 | **⚠️ 引用该槽位的规则会立刻求不出条件，变成「一行都看不到」** |

在线表单通常会自动推断槽位；原生模块的表由开发在代码里声明，一般不用手配。

### 记录分享

决定「谁可以把一条记录分享给别人」：

| 策略 | 含义 |
|---|---|
| `OWNER_ONLY`（默认） | 只有记录归属人能分享 |
| `ANY_VIEWER` | 看得见这条记录的人都能分享 |
| `DISABLED` | 禁止分享 |

留空 = 未配置 = 按默认的 `OWNER_ONLY` 执行。

> ⚠️ `OWNER_ONLY` **依赖 owner 槽位**。没配槽位时读不到归属人，
> 分享会一律被拒——这是看得见的失败，比悄悄放开安全。

> ⚠️ **「取消共享」不等于「禁止查看」**。取消共享只是删掉那条共享记录。
> 对方如果通过创建人、本部门、角色授权等别的途径本来就看得见，**取消后照样看得见**。
> 要真正挡住，得在授权列表里加一条 DENY。这个差别只有出事时才会被发现，
> 所以界面上也用橙色标注写了。

### 字段权限

列出该数据集下的列（`:col:`）和字段（`:fld:`）资源。点「配置授权」进去配字段显示模式。

看不到任何条目，说明这张表还没有登记过列/字段资源——
在线表单发布时会自动登记；原生模块由开发声明要纳管哪些字段。

### 子资源

该资源下挂的其它资源，用于往下逐层配置。

---

## 配字段权限的推荐做法

**不要逐个字段配。** 正确姿势是：

1. 在**数据集**上配一条放行（大家都能看这张表）
2. 只对**敏感字段**单独配收紧（HIDDEN 或 READONLY）

因为列和字段的默认效果是放行，没配过的字段自动可见。逐个配既累又容易漏。

### 一个典型配法

「客户表所有人可见，但手机号只有销售经理能看全，其他人看不到」：

| 主体 | 资源 | 动作 | 效果 | 字段模式 |
|---|---|---|---|---|
| ALL 所有登录用户 | 客户数据集 | VIEW | 允许 | — |
| 全体员工角色 | 客户 `:fld:mobile` | VIEW | 允许 | **HIDDEN** |
| 销售经理角色 | 客户 `:fld:mobile` | VIEW | 允许 | **EDITABLE** |

多条命中时取最严格的，所以**销售经理如果同时属于「全体员工」，会被 HIDDEN 压住**。
这种情况下不要给全体员工配 HIDDEN，改成「不配」+ 只给需要隐藏的那个角色配 HIDDEN。

> 这是实际配置中最容易踩的逻辑：**字段模式取最严格，不是「更具体的赢」。**

## 资源树是从哪来的（重要）

授权时那个资源下拉树，数据来自 `sys_resource`。**它没有增删改界面，也不该手工维护**——
它是各处配置的投影，由后端自动登记。

| 想授权的东西 | 去哪儿让它出现在资源树里 |
|---|---|
| 一个按钮 / 接口 | 【系统管理 → 菜单管理】建一个「按钮」类型的菜单，填权限标识。**保存即可用，不用重启** |
| 一张表单的行权限、列/字段权限 | 【基础设施 → 表单设计】里设计并**发布**表单，数据集与列/字段自动登记 |
| 一个流程、流程分类 | 部署流程。分类 / 流程 / 节点三级资源自动登记 |
| 一张原生数据库表 | 找开发在对应的 DO 上标 `@PermissionDataset`，声明归属人/部门/状态列 |

### 权限点是实时生效的

在菜单管理里新建一个按钮权限，保存后**资源树里立刻就有**，可以马上拿它配授权，
不需要重启后端。改权限标识、清空权限标识、删除菜单，资源行都会跟着同步。

> 表单和流程的资源仍然是**发布 / 部署时**登记的 —— 改了表单没发布、
> 改了流程没部署，资源树里不会变。这个是设计如此：
> 没发布的表单还在草稿状态，不该产生可授权对象。

### 为什么不给资源一个管理界面

资源行上的权限标识、物化路径、层级、父节点是树结构与迁移的产物，
手工改一处就可能让整棵树对不上——比如改了路径，祖先链上溯就断了、
继承关系全乱，**而且不报错**。

所以这张表只开放了「记录分享策略」一个字段可以在界面上改（见上文「记录分享」页签），
其余一律由自动登记维护。

## 管理授权主体

**入口**：资源授权弹窗里选主体类型时会自动拉对应的下拉。

角色继承关系（子角色继承父角色的授权）在主体管理里维护。
配了继承之后，子角色的人会自动拥有父角色的全部授权。

> ⚠️ 继承是**只加不减**的：父角色的 DENY 也会继承下来。

---

## 改完什么时候生效

| 改动方式 | 生效时间 |
|---|---|
| 在界面上改授权 | 立即（保存时自动清缓存），重新登录可见 |
| 在界面上改规则/槽位 | 立即 |
| 直接改数据库 | 最多 30 秒（权限清单缓存 TTL），或手动清 Redis |
| 直接改库表加/删角色 | **要手动清 `user_role_ids:<用户id>`**，否则角色不生效 |

最后一条是个常见坑：直接写 `system_user_role` 表不会失效角色缓存，
表现是「角色对了但权限是空的」。
