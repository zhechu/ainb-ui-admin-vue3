**验收标准（expect_hint · 人工评审用，本用例不机械断言）**

要给出流程编排与组织权限两个入口的菜单路径，并按先后排好顺序（先建表单或数据模型、再配审批流、最后配数据权限）；不能只给一句笼统的「在系统设置里」

**模型正文**

根据手册片段，实现该需求需分三步配置：流程权限、表单行过滤、字段权限。

1. 配置审批流程权限（让主管能批，业务员能发）

路径：【工作流程 → 流程模型】→ 找到报价流程 → 「权限配置」。
操作：
给「销售主管」角色配 MANAGE 或确保其为审批节点参与人（片段3-二）。

注意：若流程设计里已配置发起人范围，系统会自动投影授权，无需手动配 START，但需重新部署生效（片段3-一）。

2. 配置行过滤（业务员只看自己的数据）

前提：确认报价单数据集的「槽位映射」中，owner 槽位已映射到创建人列（如 create_user_id）（片段1-3.1）。
路径：【系统管理 → 角色管理】→ 找到业务员角色 → 「资源授权」。
操作：
编辑报价单的 VIEW 授权。
在「行过滤规则」中选择 仅自己的数据（片段1-3.2）。

3. 配置字段权限（可选，如需隐藏敏感信息）

路径：【系统管理 → 角色管理】→ 角色 → 「资源授权」。
操作：

4. 验证

操作：用业务员测试账号登录，检查是否只能看到自己提交的单据，且能正常发起流程（片段1-第0步，片段2-第6步）。

**验收标准（expect_hint · 人工评审用，本用例不机械断言）**

**模型正文**

根据手册，按可能性从高到低列出原因及验证方法：

联动规则只配了 LOAD/CHANGE，没配 SUBMIT

原因：服务端复校验会过滤掉未配置提交时校验的规则，导致界面虽可能显示必填（若前端生效），但接口提交空值会成功。或者因配置不完整导致前端也未生效。
验证：检查联动规则配置，确认是否包含“提交时”的校验动作；或直接构造请求绕过前端提交空值，看服务端是否拦截。
依据：【片段5】「联动规则只配 LOAD / CHANGE，没配 SUBMIT... 界面上必填，接口提交空值却成功」；【片段3】「服务端会复校验」。

期望「可见条件」当权限/必填用，或混淆了联动与可见性

原因：如果错误地使用了“可见条件”而非联动规则来控制必填，可见条件仅是界面级的，无法阻止提交。
验证：检查配置的是“联动规则”还是字段的“可见条件”。尝试直接调用 API 提交数据，看是否能绕过。
依据：【片段2】「指望『可见条件』当权限用... 改请求照样能调」；【片段3】「联动配的... 必填... 服务端在提交时会再判一遍」。

脚本 beforeSubmit 干扰或内核校验顺序问题

原因：如果在 beforeSubmit 中尝试处理必填逻辑，由于内核必填校验先于脚本执行，脚本可能根本不会触发，或者逻辑被覆盖。
验证：检查是否有挂载 beforeSubmit 的脚本试图干预此逻辑。移除脚本测试纯联动配置。
依据：【片段3】「内核的必填校验先于 beforeSubmit... 想『在 beforeSubmit 里补一个必填提示』的写法永远不会触发」。

发布缓存未更新

原因：修改配置后未重新发布，元数据缓存未刷新，导致旧配置仍在运行。
验证：执行“发布”操作，然后刷新浏览器页面重试。
依据：【片段5】「列长度改小但没重新发布... 改完要重新发布一次」（类比配置变更需发布生效）；【片段4】「保存成功、发布成功... 都不能替代它[浏览器走一遍]」。

**模型正文**

根据手册，该现象（能看到全部数据而非仅本人）通常由以下原因导致，按常见程度排序：

未真正应用行过滤规则

原因：授权上没挂规则等于「不过滤」，默认放行所有行。可能只配了 VIEW 权限但未在授权编辑中选择「仅自己的数据」。

依据：片段4-5「没配规则 = 不过滤行」；片段2-3.2

原因：用户可能通过「本部门」、「创建人」或「VIEW_ALL」等其他途径被放行。只验「能看到」无法发现配置未生效，因为默认有很多放行路径。
验证：使用【权限诊断】页查看判定路径，或用测试账号验证「配之前看不到 -> 配之后看到」的成对变化，排除其他放行路径干扰。
依据：片段4-2「只验能看到，不验看不到」；片段4-4「没配过不等于拒绝»

槽位映射缺失或错误

注意：若槽位缺失，症状通常是「一行都看不到」而非「全看到」。但若槽位配错（如映射到非创建人列），可能导致逻辑异常。
验证：检查数据集资源配置的「槽位映射」，确认 owner 槽位正确映射到记录创建人的列（如 create_user_id）。
依据：片段2-3.1；片段4-6

## 7/42 · id=31 · 业务员只看自己的报价单

**验收标准（expect_hint · 人工评审用，本用例不机械断言）**

要指明配在角色的数据权限（数据范围）上而不是菜单权限上；要说明「仅本人」这一档靠哪个字段判定归属；必须回答「为什么这样配就能隔离」，不能只给步骤

**模型正文**

配置步骤如下：

配菜单/按钮权限：在【系统管理 → 角色管理】中找到“业务员”角色，点击「资源授权」。新增授权，资源选“报价单”，动作分别配 VIEW 和 UPDATE（若需新建则加 CREATE），效果选 ALLOW。 依据：片段1「第 2 步：配菜单和按钮权限」、片段3「动作：能做什么」。
